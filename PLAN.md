## The logic of the chain
The deliverable is a set of rules: **who** is acted on, **what** happens, **how they earn back**. Rules can't be designed until four things are known:
1. **How a bad sale becomes lost money.** sale, upfront advance, first-year lapse, clawback from future pay, debt if future pay is too low, pass-up to the manager. So loss = chance of lapse x advance outstanding x share not recovered. Three places to intervene: probability, exposure, recovery.
2. **Who controls each cause of a lapse.** Ethos (wrong charge date), customer budget, or agent behavior. Accountability depends on cause.
3. **What Ethos can see, and when.** Lapses surface months later, so triggers need early signals and earn-back windows must respect that lag.
4. **What wins when levers conflict.** Decidable only after 1-3.

## Steps

### Step 1. Frame the decision (30 min)
- Question: what exactly must the doc decide, and for whom?
- Work: restate the three decisions, the reader, the constraints and what a good answer looks like.
- Done when: the deliverable can be stated in three lines.

### Step 2. Audit the case (1 hour)
- Question: what is fact, what is a stakeholder's claim, what is unknown?
- Work: sort every statement into those buckets. Treat stakeholder quotes as claims to test. For each unknown write an assumption and what would change it.
- Done when: the assumptions register exists.

### Step 3. Map how loss happens (1.5 hours)
- Question: where does money leak and how big could each leak be?
- Work: build the chain with illustrative numbers. Name non-financial harms (customer harm, polluted signals). Check whether Summit is net positive under the assumptions.
- Done when: the three-lever map (probability, exposure, recovery) and a view on Summit's economics exist.

### Step 4. Attribute causes (1 hour)
- Question: for each lapse cause, who controls it and what can Ethos observe?
- Work: cause tree with observable proxies (first-payment failure, timing clusters, premium size, replacement within a window) and each signal's lag. Note which lever fits which cause.
- Done when: an accountability map and a signal list with lags exist.

### Step 5. Extract requirements from the cases (45 min)
- Question: what does each persona force the design to handle?
- Work: Priya = small sample. Dana = Ethos-fault separation. Marcus = manager-level and concentration logic. Leo = a signal other than lapse rate. Veteran = differentiation by risk. Summit = agency-level logic.
- Done when: a requirements list exists.

### Step 6. Set priorities (1 hour)
- Question: when levers conflict, what wins and what is knowingly given up?
- Work: use Steps 3-5 as evidence. Rank cash, retention, fairness, growth. Name the sacrifices.
- Done when: every later trade-off can be resolved by the ranking.

### Step 7. Design the program (3 hours)
- Question: who, what, how back?
- Work: trigger signals and thresholds (exposure-based, minimum sample, Ethos-fault adjustment). Action ladder ordered by reversibility, each action tied to one lever. Exit criteria consistent with signal lag. Manager track. Owner per action. Counter-metric per signal. Parallel fix for the charge-date issue.
- Design rules from the case: no bespoke exceptions; reversible before irreversible.
- Done when: the program fits on one page and every Step 5 requirement has an answer.

### Step 8. Test (1.5 hours)
- Run Priya, Marcus, Dana, Leo and the veteran through the program as a test suite. Fix what fails.
- Hardest call = the case where two design principles conflict and the wrong choice is hardest to reverse.
- Done when: every agent has a justified outcome.

### Step 9. Summit, 90 days (1.5 hours)
- Apply the same program at agency level with a transition plan, an offer reflecting Summit's interests and alternatives, milestones, kill criteria and quantified accepted losses.
- Done when: the plan is consistent with Step 7. A bespoke Summit program breaks the no-exceptions rule.

### Step 10. Attack it (1 hour)
- Each stakeholder's strongest objection, a pre-mortem (day 90, it failed, why?), a "what would change my mind" line.
- Done when: the design has survived or been revised.

### Step 11. Write (3 hours)
- Recommendation first, 1-2 pages, own voice, one diagram.

### Step 12. Prototype decision and final pass (about 1 hour plus build)
- Build only if it sharpens the argument. Cut anything that doesn't change a decision. Check assumptions list and tone. Submit with buffer.

## Known weak points
- Step 3 numbers are invented. Conclusions should hold across a range.
- Step 4 proxies are guesses. The doc should say what gets validated in the first 30 days.
- Step 6 is contestable. The doc must commit and name what it gives up.
